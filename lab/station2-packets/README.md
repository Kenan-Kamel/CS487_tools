# Station 2 · An agent reads packets

`demo.pcap` is synthetic (generated by `mkpcap.py`, no dependencies). It
holds 44 frames: a DNS lookup, a cleartext HTTP login, an HTTP request with
a Basic authorization header, and a SYN sweep from a third host against 14
ports on the server. Addresses are private (10.9.0.0/24, the Lab 3 subnet).

## Runbook (10 min)

```sh
cd lab/station2-packets
tshark -r demo.pcap -q -z conv,tcp          # four TCP conversations
tshark -r demo.pcap -Y http -T fields -e ip.src -e http.request.line
claude
```

Prompts, in order. Let the students call out the next one.

1. "Summarize demo.pcap. Who talks to whom, and over what?"
2. "Is there anything a security reviewer should flag?"
3. "Decode the Authorization header in the GET /admin request."
4. "One host sends SYNs to many ports. Which ports answered, and what does that tell an attacker?"
5. "Write me the Wireshark display filter that shows only the suspicious traffic."

Then ask the room: which of these would a display filter have shown in ten
seconds, and which needed the model? Expected answer: the model is good at
the summary and at proposing the next filter; everything it "found" is a
string `tshark` already printed. It cannot see bytes `tshark` did not decode.

## If you want the agent to call tshark as a tool

Claude Code's shell tool is enough for this demo. For a tool-shaped setup,
`bx33661/Wireshark-MCP` on PyPI (`wireshark-mcp`, Python 3.10+) wraps tshark
as an MCP server. There is no official Wireshark MCP integration as of Nov 2026.

## Regenerating

`python3 mkpcap.py` rewrites `demo.pcap`. Edit the hosts, credentials, or
port list at the top of the script.
